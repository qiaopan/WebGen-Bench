\begin{abstract}
Agents that generate websites with large language models solve every task from scratch: what went wrong on one website is forgotten before the next one starts. This dissertation asks whether a system built around a \emph{small} generator, WebGen-LM-7B, can improve across a sequence of WebGen-Bench tasks when it is given a long-term memory built from its own earlier attempts, without changing its weights and while retaining the official single-attempt generation and evaluation of each task. The memory is maintained by a separate, larger model; only the generator is small.

We first reproduce the official No Memory baseline on a self-hosted cluster (28.5\% accuracy on 101 tasks versus 28.4\% reported). Its failures show that many zero-score tasks are blank pages caused by basic code errors, such as importing a package that is not installed, and, in a nine-task diagnostic, short textual warnings did not reliably prevent these failures. A text-dominated memory improved early performance but later fell behind No Memory; the experiments do not isolate the cause of this decline.

Code memory adds a requirement checklist and a code pool: when earlier tasks show a code error that breaks a site, the prompt carries a short fragment copied verbatim from the chain's own compiled, successful websites. In a single run over all 101 tasks it reaches 40.0\% against 28.5\% (paired gain 11.5 points, 95\% CI 6.0--16.9) and cuts zero-score tasks from 30 to 13; a checklist-only ablation gains 3.4 points, suggesting that the stored cross-task content accounts for most of the improvement in this run. Under shuffled task orders, a whole-file example made the generator return the untouched starter project. The final version (v9.1) shows only verified lines of such files; no scaffold returns were observed in either shuffled-order run, with gains of 7.4 and 5.5 points. \todo{Add v9.1 on the manifest order.} Gains are in functional accuracy, largely from sites that now render; appearance on sites that work in both arms is similar.

The main observation is that, for this small generator, the \emph{form} of memory mattered: short code fragments were followed where textual lessons were not. All results are single runs on one benchmark on which the method was also developed; we discuss these limits, the cost of the larger memory model, and the ethical considerations of code agents that change their behaviour from experience. \todo{Status: fixed-prefix ablation queued; its result decides whether the gain is described as accumulated memory or as automatically discovered prompt code.}
\end{abstract}
