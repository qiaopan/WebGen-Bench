\begin{abstract}
Website-generation agents solve every task from scratch, forgetting what went wrong on earlier websites. This dissertation asks whether a system built around a \emph{small} generator, WebGen-LM-7B, can improve across a sequence of WebGen-Bench tasks when it is given a long-term memory built from its own earlier attempts, without changing its weights and while retaining the official single-attempt generation and evaluation of each task. A separate, larger model maintains the memory.

We reproduce the official No Memory baseline on a self-hosted cluster (28.5\% accuracy on 101 tasks; 28.4\% reported). Its failures show that many zero-score tasks are blank pages caused by basic code errors, such as importing a package that is not installed, and, in a nine-task diagnostic, short textual warnings did not reliably prevent these failures. A text-dominated memory improved early performance but later fell behind No Memory; the experiments do not isolate the cause of this decline.

The final method, code memory, adds a requirement checklist and a code pool: when earlier tasks show a code error that breaks a site, the prompt carries a short fragment copied verbatim from the chain's own compiled, successful websites. In a single run over all 101 tasks it reaches 35.2\% against 28.5\% (paired gain 7.1 points, 95\% CI 0.9--13.1), and it gains 7.4 and 5.5 points in two shuffled orders, one of which was used to develop it. An intermediate version that sometimes showed whole files scored higher in the original order (40.0\%) but made the generator return the untouched starter project in shuffled orders; fragments removed this failure. Gains are functional, largely from sites that now render; appearance on sites working in both arms is similar.

In these runs, short code fragments reduced the targeted failures, whereas textual warnings did not reliably prevent them. \end{abstract}
