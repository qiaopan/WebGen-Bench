\section{Answers to the Research Questions}
\paragraph{\ref{rq1}} The answer is a qualified yes for WebGen-LM-7B with Bolt.diy on WebGen-Bench. The final code-memory method raises accuracy from 28.5\% to 35.2\% ($+7.1$, with a confidence interval excluding zero) and reduces zero-score tasks from 30 to 20. It also gains 7.4 and 5.5 points in two shuffled orders. Most of the gain comes from sites that render successfully. The gain is positive in all five task orders ($+5.5$ to $+11.7$ points), with an interval excluding zero in four.

\paragraph{\ref{rq2}} In these runs, the small generator followed short code fragments from its earlier websites more readily than textual lessons. Text memory fell below No Memory late in the sequence, although this is a cross-version rather than controlled comparison. The checklist-only control adds little ($+3.4$, with an interval including zero). Fragments also need to remain partial: complete files can be copied as finished answers. \todo{Status: add the fixed-prefix result (queued after seed 47).}

\paragraph{\ref{rq3}} Code memory maintains an advantage over the sequence (35.3\% versus 29.5\% on tasks 31--101), whereas text memory declines. This pattern is consistent with learning from experience but does not prove it. Whole-file examples cause scaffold outputs when order changes. Verified fragments remove those scaffolds, and their gain is positive in all five orders, with domains both adjacent and mixed; the interval includes zero only for seed 29. Whole-file code memory scores higher only in the original order (40.0\%).

\section{Future Work}
Two experiments would address the most important remaining uncertainties.
\begin{itemize}
  \item \textbf{Held-out evaluation.} Because the method was developed while observing results on all 101 tasks, a clean evaluation requires tasks that were not used in development. Suitable options include a held-out domain or a second website-generation benchmark, with the method frozen in advance.
  \item \textbf{Controlled comparison of memory forms.} Retrieval, trigger conditions, and token budget should be fixed while varying only the representation: textual rule, pseudocode, short fragment, complete file, plus random-code and length-matched-text controls.
  \item \textbf{A second generator.} Repeating the comparison with a stronger generator, such as WebGen-LM-32B, under the same pipeline would show whether code fragments remain more useful than textual lessons when the generator follows text better.
\end{itemize}
Other priorities are repeated runs for each order, which would separate order effects from run-to-run variation, and testing larger generators from the same family with a text-memory arm to determine whether the preference for code depends on model size.
