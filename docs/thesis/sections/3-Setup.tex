\chapter{Experimental Setup}
\label{chap:setup}

\section{Benchmark and Protocol}
We use all 101 WebGen-Bench tasks in the benchmark's manifest order, which groups tasks into 20 domain blocks. We follow the official protocol: the generator produces the project once, there is no repair loop, and a project is passed to evaluation as soon as its dependencies install and the development server starts. Test cases without an evaluation record count as failed, as in the official scoring script. An earlier phase of this project used a stricter build gate (\texttt{vue-tsc}) and a more generous repair loop; those results are not comparable with the paper and are not reported as main results.

\section{Models and Roles}
All models are self-hosted on the university CS ML cluster (two NVIDIA H200 GPUs per job, served with vLLM). No commercial \gls{llm} service is called. \Cref{tab:roles} lists the roles.

The memory model is deliberately different from the evaluator, so that reflection cannot copy the evaluator's grading behaviour. vLLM applies the model repository's generation configuration by default; WebGen-LM-7B ships with a repetition penalty that Bolt.diy never sends, so we disable it for the generator to match the paper's setting.

\section{Metrics}
For each task with $n$ test cases, of which $p$ pass and $q$ are partial,
\begin{equation}
\text{accuracy} = \frac{p + 0.5\,q}{n}.
\end{equation}
We report accuracy over all test cases, the mean appearance score (1--5), and the number of \emph{zero-score} tasks. Because test cases within a task are not independent, comparisons are paired by task rather than by test case.

\section{Arms}
\begin{description}
  \item[No Memory] The requirement alone. No retrieval, no reflection, no memory writes.
  \item[Long Memory (v4, v7)] The requirement plus memory content, written from the chain's own earlier tasks (\Cref{chap:method}).
  \item[Checklist only] v7 with memory writing disabled, so each task sees only the requirement checklist. This isolates the effect of the prompt restructuring from that of memory.
\end{description}
Memory never uses information from the current task itself (leave-one-task-out), and evaluation results are never fed back into the same task.

\section{Reproducing the Baseline}
No Memory on all 101 tasks reaches 28.5\% accuracy (paper: 28.4\%) with a mean appearance score of 2.34 (paper: 2.5 with GPT-4o) and 30 zero-score tasks. The close match in accuracy gives us confidence that the self-hosted pipeline is faithful to the official one.
