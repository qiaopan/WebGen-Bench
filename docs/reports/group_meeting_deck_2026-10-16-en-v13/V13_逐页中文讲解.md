# V13 PPT 逐页中文讲解（自己看，不放进 PPT）

## 第 1 页：标题
小模型能不能靠"长期记忆"把网站做得更好？副标题：文字经验 vs 代码示例。

## 第 2 页：任务和问题
- **WebGen-Bench**：101 个建网站的需求，来自 20 个领域（电商、博客、论坛……）。网站做出来后，一个会"点网页"的 AI 测试员逐项点按钮，检查功能是否正常。
- **长期记忆**：每做完一题，系统记下哪里出错；后面的题可以用这些记录。
- **问题**：模型做的题越多，会不会越做越好？

## 第 3 页：整体流程
- 黑色部分 = 官方原本的流程（No Memory）：需求 → 7B 模型在 Bolt 里写网站 → 32B 视觉模型当测试员打分。
- 蓝色部分 = 我们加的记忆：做完一题，72B 记忆模型反思错误、存下修法；做下一题前，往 prompt 里加一份需求清单和代码示例。
- 重点：生成模型、测试员、规则都没变，**只改了模型读到的文字**。

## 第 4 页：设置
四个角色各用什么模型；评分 = (通过 + 0.5×部分通过) / 检查项数。我们的 No Memory 是 28.5%，论文是 28.4%，说明我们的复现是对的。

## 第 5 页：模型和算力
WebGen-LM-7B 是论文作者用 Qwen2.5-Coder-7B 专门为 Bolt 微调的，所以它天生会 Bolt 的输出格式。全部跑在学校两张 H200 上，不花钱买 API。

## 第 6 页：实验（V13 已改成两张表）
**上表：比较了哪几组**

| 组 | 中文意思 | 回答的问题 |
|---|---|---|
| No Memory | 不加任何记忆，官方原样 | 基线对不对 |
| Text memory | 记忆是**文字教训**（"表单要能提交"这类话） | 文字经验有没有用 |
| Checklist only | 只把需求拆成清单，不读不写记忆 | 光拆需求有没有用 |
| Code memory (whole-file) | 记忆里放**代码示例**，有些是整份文件 | 代码示例有没有用 |
| Code memory (fragments) | 最终方法：代码示例只放几行关键代码 | 换顺序还稳不稳 |
| Fixed code prefix | 从第 1 题就塞固定代码，不学习 | 是"学到的"，还是"prompt 里有代码"就行 |

**下表：四种任务顺序**（老师可能问"这些顺序有什么区别"）

| 名称 | 怎么排 | 举例 |
|---|---|---|
| Original（原顺序） | 官方列表顺序，同领域的题一个接一个 | 8 个电商题连着做，再做 8 个论坛题 |
| Shuffled, domains grouped（领域内打乱） | 领域的先后打乱，领域内的题也打乱，但同领域的题**还挨在一起** | 先做论坛（顺序打乱），再做电商…… |
| Fully random（完全打乱，跨领域） | 101 题全部随机，领域混在一起 | 电商、博客、论坛随便交替 |
| Alternating（交替，在跑） | 每一题都换一个领域 | 电商→博客→论坛→电商…… |

为什么要换顺序：记忆只能用"前面做过的题"。原顺序里同领域连着做，后一题总能抄到刚做过的相似网站，结果可能偏好。换顺序是检查"记忆真的有用，而不是顺序占便宜"。

## 第 7 页：第一次尝试，文字经验
前 30 题文字记忆比 No Memory 高（39.3% vs 26.0%），后 41 题反而更低（22.9% vs 24.8%）。原因：越往后 prompt 里塞满"确保表单能用"这类空话，小模型照不了。

## 第 9 页：关键发现
网页空白的那些题，给一句文字提示只救回 1/3，给一段 10 行代码示例救回 7/9。结论：**小模型听代码，不听文字。**

## 第 10 页：方法（代码记忆的两部分）
1. 需求清单：72B 把需求拆成一条条，经验挂在对应条目下面，需求永远放最前面。
2. 代码池：同一种代码错误在 2 道题出现过，就从自己以前做成功的网站里摘一小段正确写法，编译通过才用。

## 第 11 页：三种记忆设计（whole-file vs fragment 重点）
- **Text memory（文字记忆）**：给模型的是一句句话，比如"记得 import ref"。小模型不听。
- **Code memory (whole-file)（整文件代码记忆）**：给模型的是从以前成功网站复制来的代码，**有些是整份文件**，比如一整个 `App.vue`（网站的主文件，几十行）。问题：模型看到一份"完整的文件"，以为这就是答案，直接照抄交上去，交的是一个空壳网站（Vite 默认首页）。
- **Code memory (fragments)（片段代码记忆，最终方法）**：同样从以前成功网站取代码，但**只取最关键的几行（最多 15 行）**，比如"import { ref } from 'vue'"加一行用法。模型知道"该这么写"，但不会把它当成整份答案抄。
- 打比方：整文件 = 给学生一整份别人的作文，学生直接交了；片段 = 只给一句好的开头示范，学生还得自己写全文。
- Checklist only 是消融：只拆需求、不用记忆，只多 3.4 分，置信区间包含 0，说明主要提升来自记忆。

## 第 12 页：主结果
101 题：28.5% → 40.0%，0 分题 30 → 13。按题配对平均多 11.5 分，95% 置信区间 6.0–16.9，不包含 0（说明提升不太可能是运气）。

## 第 15 页：换顺序（V13 已调整）
- **表格**：换成两种新顺序后，整文件版本交了很多空壳网站（19 个、16 个），片段版本是 0 个。已删掉"增益"那一列，只看空壳数。
- **折线图**：领域内打乱这个顺序下，"片段版本分数 − No Memory 分数"，按最近 10 题求平均。**线在 0 以上 = 这段时间有记忆的更好**；大部分时间在 0 以上，中间有几段掉到 0 以下（那几段题记忆没帮上忙）。最后一段 +22。
- 一句话讲：整份文件会被模型直接抄成空网站，只给片段就不会。

## 第 16 页：局限和下一步
- 局限：每种顺序只跑一次（论文也只跑一次）；提升在功能，不在外观；只用了一个模型、一个工具（Bolt + Vue）；方法是在这 101 题上调出来的（用两种新顺序检查过）。
- 下一步：剩下的实验 10-16～18 跑完；10-19 交论文初稿给导师。

## 第 18 页：结论
小模型的记忆应该给代码，不要给建议。28.5% → 40.0%，大部分提升来自记忆。

---
**可能被问的问题（简短答法）**
- *为什么不给文字？* 7B 模型照文字做的比例很低，照代码做的比例高（第 9 页：1/3 vs 7/9）。
- *片段和整文件差在哪？* 整文件会被当成答案直接抄；片段只示范关键写法。
- *为什么要打乱顺序？* 记忆只能用前面的题；原顺序同领域连着做，可能占便宜。
- *置信区间不含 0 是什么意思？* 把 101 道题反复有放回地重抽样，算出的增益范围整体在 0 以上，提升不太像运气。
