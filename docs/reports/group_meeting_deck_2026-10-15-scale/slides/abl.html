提升来自需求拆解，还是记忆？

组别前 30后 71全部
No Memory26.0%29.5%28.5%
只有清单（不注入经验）33.1%31.3%31.8%
v7（清单 + 记忆）39.0%40.4%40.0%

按题配对：只有清单 − No Memory +3.4（CI −2.2～8.7，不显著）；v7 − 只有清单 +8.1（CI 2.9～13.2）。零分题 30 → 18 → 13。

单次运行，101 题，manifest 顺序。只有清单 = v7 配置，但不读写任何记忆。

消融回答“提升从哪来”。只有清单这一组和 v7 配置完全相同，但不读也不写任何记忆，每题都从空记忆开始，所以它减去 No Memory 就是需求拆解的贡献，v7 减去它就是记忆的贡献。结果：只有清单比 No Memory 高 3.4 个点，但置信区间跨零，不显著；它主要把零分题从 30 降到 18，减少整站做不出来的情况，而且优势在第 31 题以后从 7 个点缩到不到 2 个点。在清单之上加记忆又高 8.1 个点，置信区间不跨零，而且后段比前段更大。所以主要贡献来自记忆。要注意清单是由 72B 记忆模型拆出来的，准确地说是更强的模型替小模型拆需求。还有一个问题我们准备用“固定前缀”消融回答：从第一题起直接给代码、不读写记忆，看起作用的是记忆的积累，还是 prompt 里有代码就够，放在下一步里讲。
