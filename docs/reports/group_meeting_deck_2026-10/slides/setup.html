全部自部署，复现官方基线

角色设置
生成器WebGen-LM-7B（vLLM），Bolt.diy，只生成一次、不修复
功能 / 外观评测Qwen2.5-VL-32B（论文外观用 GPT-4o，这是唯一偏差）
记忆 / 反思Qwen2.5-VL-72B-AWQ + bge-m3
硬件学校集群 2×H200，单个任务约 12 分钟
指标准确率 =（通过 + 0.5×部分通过）/ 检查数；外观 1–5；零分题数
基线复现No Memory 101 题 28.5%（论文 28.4%，Lu et al., 2025）
原论文局限单次运行、无误差线（自查清单：计算成本太高）；只覆盖 TS/JS/CSS/HTML；只用监督微调
实验设置。全部模型都部署在学校集群上，不调用任何商业 API。生成器是 WebGen-LM-7B，用 Bolt.diy，只生成一次、不修复。功能和外观评测都用 Qwen2.5-VL-32B；论文的外观评测用 GPT-4o，这是唯一的偏差，所以外观分只在我们自己的组之间比较。记忆和反思用 72B 模型。单个任务大约 12 分钟。准确率等于通过数加一半的部分通过数，除以检查数。No Memory 复现出 28.5%，和论文的 28.4% 几乎一样，说明评测管线是可信的。最后一行是原论文的局限：它的结果都是单次运行、没有误差线，作者在自查清单里说是因为计算成本太高；论文自己写的局限是只覆盖 TypeScript、JavaScript、CSS、HTML，以及只用了监督微调。因为我们要比较的两组差距可能和运行波动差不多大，所以我们重复了 No Memory，并在另外两种顺序下重跑 Long Memory，后面顺序实验会讲。
